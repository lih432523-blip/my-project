## 一 工作范围与项目基础

成员 A 负责课程模块四的前端部分：通过界面组织已有 RAG 与 Agent 能力，让用户能够上传论文、建立知识库、提问和查看来源。检索、Embedding、重排序、ReAct 决策及 Memory 算法由 C/D 提供，本次不重新实现这些算法。

开发前已阅读课程要求、小组分工、C 到 D 的交接说明、D 到 A/B 的接口说明、现有 Python 代码及实验记录。当前下载项目包含三篇示例论文，C 已提供 PDF 加载、三种分块策略、向量检索、BM25、RRF、Reranker 和 RAG 生成接口；D 已提供统一 `agent_chat()`、路由、工具、会话记忆、执行日志及健康检查。原项目没有 Streamlit 页面。

本次实现以这些接口为基础。现有交接文档中的服务器测试结果属于此前开发环境的记录，不能直接等同于本次前端或当前本机已经验证通过。

## 二 已实现的前端功能

### 文档管理与知识库状态

左侧文档面板支持批量选择 PDF、上传进度、单文件处理结果、论文列表、文件大小、原文下载以及确认删除。每份文件限制为 50 MB；空文件、非 PDF 内容及不安全的文件路径会被拒绝。相同文件重复上传时跳过，同名但内容不同的文件不会覆盖原文件。

删除论文采用移动到 `data/.trash/` 的方式，文件仍可恢复。文档发生变化后，接入层使旧索引失效；后续论文问答会先更新知识库，避免继续使用过期检索数据。

“构建 / 更新知识库”调用 D 的 `refresh_knowledge_base()`，并展示处理中、成功或失败状态。论文列表区分“待向量化”“已向量化”“待恢复索引”和“建库失败，可重试”。建库失败后可以再次操作；没有可提取文本的扫描件会提示需要 OCR。

当前 C 的加载器只支持 PDF，因此上传控件只开放 PDF。建库仍使用现有全量重建接口，不能称为增量向量化。

### 聊天与回答展示

中央区域提供用户输入、聊天消息、Markdown 回答和逐字展示开关。提问时显示 Agent 处理状态；完成后展示答案、调用工具、执行步骤和总耗时。空问题、超长问题、空知识库论文提问及后端异常都有对应提示。

问答通过统一 `agent_chat()` 接口执行。当前后端一次返回完整答案，因此逐字效果属于展示层流式输出，尚不是模型生成期间的 token 实时推送。

### 引用来源与原文下载

回答下方展示后端实际返回的来源文件、页码及可用的重排序分数，同一文件与页码的重复记录会合并。用户可下载对应原文核对答案。

后端没有返回引用时，界面明确显示无引用；原文件已删除时保留历史来源信息并提示文件不可下载。重排序分数只反映检索排序，不能作为答案正确率。

### 历史会话与持久化

历史面板支持新建、切换、重命名、删除及导出会话。不同会话使用不同 UUID 传入 Agent；删除会话时同时清理对应的后端记忆。

聊天内容、引用和执行结果保存到 `.runtime/sessions/`，使用原子写入保护记录。保留带 `workspace` 参数的浏览器地址，可以在刷新或服务重启后重新打开同一工作区。Markdown 导出适合整理报告材料，JSON 导出保留执行结果，便于后续测试分析。

服务重启后再次提问时，接入层使用 D 的既有接口恢复最近 12 条消息及最近确认的论文。全部对话仍保留在界面历史中，但没有完整持久化 D 的长期压缩摘要。

### Agent 执行记录与系统状态

折叠区域按步骤展示后端返回的路由、执行计划、工具、输入、输出和错误记录。直接工具调用的结果也可作为工具输出展示。当前 trace 在任务完成后返回，尚不能实时显示每一步正在执行的事件。

系统面板展示 Ollama、问答模型、索引状态、依赖检查，以及真实日志中的请求数量、成功率、平均耗时和平均步骤。Token 与检索耗时只有在返回字段可用时才显示，缺失时标为“未提供”；检索命中率标为“待评测”。

本机项目另外做了少量兼容修复，包括将重型模型导入延后、将运行路径改为共享配置、补齐 `load_pdf` 导入及统一日志目录。这些修改已在技术实现文档中列出，未打入只包含新增前端文件的服务器包，交接时应由 C/D 根据服务器代码版本决定是否合并。

前端依赖现有的 `agent_chat()`、`refresh_knowledge_base()`、健康检查、指标和 Memory 接口。接入层用锁协调同一进程内的问答与索引变化；会话隔离不等于知识库隔离，多个工作区仍使用同一论文库。

## 五 当前项目缺口与后续分工

以下判断针对当前下载的项目代码和材料，不代表团队其他未提供的分支或服务器上也一定缺少这些内容。负责人是依据既有分工提出的对接建议。

| 缺口 | 当前影响 | 建议对接成员 |
| --- | --- | --- |
| 前端尚未在真实环境验收 | 浏览器交互、依赖兼容和完整问答链路仍需检查 | D 负责联调，B 负责验证 |
| 系统截图尚未生成 | 课程报告缺少实际界面图片 | 运行验证人员生成，B 汇总 |
| 模型和工具没有统一的实时事件接口 | 回答只能在完成后逐字展示，trace 只能完成后查看 | C/D 提供接口，再接前端 |
| Word、TXT、Markdown 加载器尚未提供 | 当前只能上传 PDF | C |
| 索引更新仍是全量重建 | 新增文档需要重新处理已有文档；重启后需恢复内存检索器 | C/D |
| RAG 语义缓存未在当前代码中实现 | 相近问题仍可能重复检索和生成 | C |
| RAG 上下文长度与低相关度处理尚不完整 | 超长上下文、低质量召回及模型失败需进一步完善降级策略 | C/D |
| Token、各工具耗时等字段不完整 | 前端无法完整展示课程要求的运行指标 | C/D |
| 工具注册数为 7，课程要求为 8 | 工具数量仍需补齐或确认教师允许的调整 | D |
| 工具调用是同步执行，未见并行调度及独立超时控制 | 多工具执行效率和卡住时的恢复能力仍需完善 | D |
| 只有 3 篇示例论文 | 尚未达到模块五建议的 10–20 篇评测文献规模 | B 协调，C 导入 |

| 分块 CSV 主要记录块数和长度 | 不能据此证明 Hit@5、MRR、Recall 的改进 | C 提供实验，B 整理 |
| 未见完整性能报告、Bad Case 迭代结果及部署文件 | 项目整体交付仍需补齐报告、部署和演示材料 | B/D，各成员提供模块材料 |

建议首先完成一次真实环境的前端验收，确认上传、建库、问答、引用和会话操作，再补齐课程明确要求的工具、指标、文档格式与评测材料。评测数字和截图应来自实际运行，不能以功能代码存在或历史交接文档代替。
