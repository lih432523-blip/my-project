三组正式运行均完成：每组55题×3档检索，共495条，0失败。已核对题集/语料指纹、后端源码、Python依赖、Embedding/Reranker及CPU配置一致，并从逐题原始sources重新计算全部三项质量指标，与原汇总一致。

## 本次结论

建议后续Agent优化复测继续固定chunk_size=512及混合＋重排，避免同时更换检索参数与Agent代码导致归因不清。

- 512与1024均命中46/55题，Hit@5同为83.64%。512的MRR@5为0.6245，高于1024的0.5921；Recall为72.73%，高于71.36%。
- 512重排平均耗时1.786秒，1024为3.258秒。这里是单次串行实测，不宣称显著性。
- 256重排更快（1.312秒），但只命中42/55题、Recall为64.24%。若重视本评测集的质量，512更合适。
- RRF混合本身不保证所有指标改善，例如512的混合Recall低于纯向量；三种大小在加入重排后均提高Hit与Recall，但增加查询耗时。

## 实验边界

- All three sizes use recursive character chunking; this is not a fixed/recursive/semantic strategy comparison.
- overlap parameter is 50; the current recursive implementation does not guarantee 50-character overlap between every pair of emitted chunks.
- 512 reuses an index; build_index_s=0 cannot be compared as new-index construction speed.
- Single serial CPU run per configuration on 55 questions; no claim of statistical significance or universal optimality.
- Retrieval quality does not establish answer correctness or completion of a generation/Agent optimization experiment.

指标按PDF文件名与物理页码判断证据页命中，并非逐句引用正确率。候选召回20、最终Top-5；题集含多证据问题，所以Recall与Hit可以不同。没有进行新的答案生成或优化复测。
